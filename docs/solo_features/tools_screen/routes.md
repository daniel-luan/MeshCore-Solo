# Planned routes

Solo supports one saved hiking route independently of trail recording. Open **Tools → Location → Routes**. Left/right selects Overview, Navigate, Route View, Elevation, or Checkpoints; up/down scrolls the overview or checkpoints. Hold Enter for route actions: forward/reverse, stop, rejoin, next segment, alert settings, and confirmed deletion.

## Import from GPX

Serve the repository's static tool locally:

```sh
python3 -m http.server 8000
```

Open `http://localhost:8000/tools/gpx-downloader/` in desktop Chrome and select **Import route**. Disconnect BLE companions and other USB applications. Select a GPX 1.0/1.1 file, choose a track/route and checkpoints, and inspect its segment boundaries. The file stays on your computer. Geometry is preserved by default; optional horizontal/elevation simplification retains endpoints, segment boundaries, and selected checkpoint legs. Missing elevation remains missing.

Connect at 115200 baud, review capacity, then import. Transfers and verification show progress; cancellation or interrupted replacement retains the previous complete route. There is no 32 KB route limit: filesystem space, reserve, overhead, and the existing route determine replacement capacity. Only the inactive slot is reclaimed automatically. To reclaim the active route, explicitly delete it on the device.

## Following a route

The Heltec V4 needs a connected GPS receiver. Starting with GPS off offers to enable it. Navigation keeps GPS awake even with the display off. Reboot keeps the route but stops navigation.

Matching requires a fix no older than five seconds, plus HDOP ≤ 3.0 (or four satellites when HDOP is unavailable). Poor/stale fixes suspend progress and alerts. Course is the last observed direction of movement, not a stationary compass heading. Remaining distance excludes gaps between GPX segments; reaching a segment end requires **Next segment** to continue. At ambiguous crossings, move onto the intended leg and choose **Rejoin route**.

An off-route excursion defaults to >50 m for 15 seconds, clearing below 25 m. Adjust distance and delay in Route actions. Alerts obey existing sound/wake preferences. Checkpoints show both path distance and lateral offset; an offset point is not implied to be on the trail.

Route View uses a solid planned line and dotted recorded trail. The elevation profile uses up to 64 preview samples, shows navigation progress, and breaks at missing heights and segment gaps. It is an overview, not a detailed topographic map. Import/checking overlays appear only while the display is already on. Diagnostics includes route I/O, verification, and search maxima; small reads cannot eliminate filesystem stalls.

## Development checks

```sh
node --test tools/gpx-downloader/routes/format.test.mjs
pio test -e native -e native_kiss_modem
pio run -e heltec_v4_companion_solo_dual
pio run -e WioTrackerL1_companion_solo_dual
```

Run PlatformIO tests and builds sequentially. Native fake-filesystem tests cover power loss during verification/activation, truncated footers, corrupt generations/indexes, capacity errors, duplicate chunks, reverse segments, crossings, and stale fixes. Canonical binary fixtures are generated by the JavaScript converter; regenerate with `ROUTE_FIXTURE_DIR=test/test_routes/fixtures node --test tools/gpx-downloader/routes/format.test.mjs`.

Chrome integration tests require Python Playwright and Chromium: `python tools/gpx-downloader/routes/browser_test.py`. Optionally set `CHROMIUM_PATH` to an installed Chromium executable. These tests use a simulated USB device; physical imports, GPS walks, power cuts, notifications, and switch operation still need device validation.

The implementation contract is documented in [Route format and USB protocol](../../route-protocol.md).
